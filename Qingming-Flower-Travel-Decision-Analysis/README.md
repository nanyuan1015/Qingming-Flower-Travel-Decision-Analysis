# 清明赏花旅游决策分析

本项目围绕清明假期赏花出行，整理多城市历史天气记录与花期数据，构建可复现的数据分析流程，覆盖天气特征汇总、花期趋势基线预测、历史花期重叠分析和可视化输出。分析主题对应清明天气、花期、出行决策与赏花经济四类问题；当前实现重点落在天气数据整理、花期探索分析和观赏窗口计算。

## 项目内容

- 汇总西安、杭州、武汉、郑州、毕节和吐鲁番六个有原始天气文件城市的清明时段记录，比较气温、湿度和天气现象代码。
- 整理五类花卉的历史始花日期与持续时间，使用按年份滚动验证评估线性趋势基线，并生成探索性2026趋势预测。
- 计算历史花期与清明假期的重叠时长，作为出行日期与观赏窗口分析的基础。
- 输出CSV结果和图表，便于复查、扩展和用于后续路线决策建模。

## 方法与技术

Python、Pandas、NumPy、scikit-learn、Matplotlib、Seaborn。分析包括Excel数据读取、日期清洗、描述性统计、按时间顺序的滚动验证、线性趋势基线和结果可视化。

## 运行

建议 Python 3.10 或更新版本：

```bash
python -m pip install -r requirements.txt
python src/analyze_project.py
```

脚本从项目内 `data/` 读取数据，并在 `results/` 输出CSV、PNG图表和运行摘要。

## 数据与解释

题目列出的七座城市为西安、吐鲁番、婺源、杭州、毕节、武汉、洛阳。当前收到的天气原始文件对应西安、吐鲁番、杭州、毕节、武汉和郑州，缺少婺源、洛阳的原始天气文件；因此分析只报告有文件支持的六个城市，郑州作为现有数据城市单独保留，不把它替代成洛阳。各城市历史记录时间跨度和采样间隔也不一致。

天气数据采集说明称城市气象记录参考 rp5.ru 历史天气页面，花期资料整理参考相关论文与物候文献。新增数据包中的六个城市工作簿与当前项目文件逐个比对后内容相同，没有增加观测记录；因此不重复存储。说明材料还指出天气数据存在缺失/异常值待处理及城市替代情况。当前项目使用已提供的清洗后城市表做基础字段整理，但不将它们表述为独立官方站点下载数据。题目和采集说明 PDF 均未放入项目压缩包。

天气原始表按文件所含记录整理。随附数据说明将 WW=1 定义为有雨、WW=0 定义为无雨；项目据此汇总有雨记录占比。该二元字段不包含逐时降水量和持续时间，不能直接验证论文中的“雨纷纷”阈值判定。各城市天气文件所覆盖年份和采样频率不完全一致，比较时应同时查看样本量与记录年份。旧分析表中洛阳、婺源的行与其他城市数据相同，而原始数据包没有这两座城市的天气文件，因此本项目不把重复映射行当作独立城市天气观测。

花期数据来自所提供的工作簿。原表采用分组标题与合并单元格排版，脚本会向下补齐花卉和地区标签；少数异常或缺失日期会跳过。花期样本数量较少，2026结果属于按年份外推的探索性趋势基线，不代表经过外部验证的物候预报。

花期重叠表使用地区到城市的对应关系作为分析假设，因为当前花期表主要按地区整理，不包含目标城市或景区逐一观测的花期。该结果用于展示计算流程，进一步应用前应补充城市/景区实测花期资料并核实地区映射。

## 当前分析边界

现有输入支持天气与花期的探索性分析，但尚未提供完整的目标七城天气资料、统一口径的城市间交通时间、景区客流/承载量、票价与旅游消费数据。因此，本项目不输出已验证的最优路线或真实经济收益提升率。后续可接入这些数据，再实现带时间和容量约束的路线优化及可解释的收益情景分析。
